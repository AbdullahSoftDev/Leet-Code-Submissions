## Problem Statement

You are given an integer array `prices` where `prices[i]` is the price of a given stock on the `i`-th day.

On each day, you may decide to buy and/or sell the stock. You can only hold **at most one share** of the stock at any time. However, you can sell and buy the stock multiple times on the same day, ensuring you never hold more than one share of the stock at once.

**Find and return the maximum profit you can achieve.**

---

## Examples

### Example 1
```
Input:  prices = [7,1,5,3,6,4]
Output: 7
```
**Explanation:**
Buy on day 2 (price = 1) and sell on day 3 (price = 5), profit = 5 - 1 = 4.
Then buy on day 4 (price = 3) and sell on day 5 (price = 6), profit = 6 - 3 = 3.
Total profit = 4 + 3 = **7**.

### Example 2
```
Input:  prices = [1,2,3,4,5]
Output: 4
```
**Explanation:**
Buy on day 1 (price = 1) and sell on day 5 (price = 5), profit = 5 - 1 = **4**.
Total profit is 4.

### Example 3
```
Input:  prices = [7,6,4,3,1]
Output: 0
```
**Explanation:**
There is no way to make a positive profit, so the maximum profit is **0** (never buy the stock).

## Constraints

- `1 <= prices.length <= 3 * 10^4`
- `0 <= prices[i] <= 10^4`

## Intuition

The key difference between this problem and "Best Time to Buy and Sell Stock I" is that here you're allowed **unlimited transactions** instead of just one buy and one sell. That extra freedom actually makes the problem *easier*, not harder — you no longer need to track a single global minimum price; you just need to react to each day-to-day price movement.

Think about the total profit across any stretch of days as the sum of every daily price change:

```
(sell_price - buy_price) = (p2 - p1) + (p3 - p2) + (p4 - p3) + ... + (pn - p(n-1))
```

This is a **telescoping sum** — all the intermediate terms cancel out, leaving just `pn - p1`. That means summing every single day-to-day change (positive or negative) across a range always equals the profit of buying at the start and selling at the end of that range.

Since we're free to choose *which* days to trade on, the optimal strategy is to only "keep" the days where the price goes up, and skip (contribute nothing for) the days where it goes down. In other words: **capture every positive price movement, ignore every negative one.**

---

## Approach

1. Initialize a variable `total` (or `max_profit`) to `0`. This will hold the running sum of profit.
2. Iterate through the `prices` array starting from index `1` (comparing each day to the day before it).
3. On each iteration, check if `prices[i] > prices[i - 1]`:
   - If **yes**, the price went up — add the difference `prices[i] - prices[i - 1]` to `total`. This models "buying yesterday, selling today."
   - If **no**, the price went down or stayed the same — do nothing, since there's no benefit to trading on a down day.
4. After the loop completes, `total` holds the maximum achievable profit. Return it.

This is a classic **greedy algorithm**: at each step, make the locally optimal choice (capture the gain if there is one) and this leads to a globally optimal result.

---

## Why the Greedy Approach Works

It might feel unintuitive that grabbing every small up-move gives the same result as carefully picking a few big buy/sell pairs — but the math guarantees it.

Consider any profitable buy-low/sell-high pair, say buy on day `a` and sell on day `b` (`b > a`). The profit is:

```
prices[b] - prices[a]
```

Now expand this as a sum of every daily change between day `a` and day `b`:

```
prices[b] - prices[a]
= (prices[a+1] - prices[a]) + (prices[a+2] - prices[a+1]) + ... + (prices[b] - prices[b-1])
```

Every middle term cancels: `-prices[a+1] + prices[a+1]`, `-prices[a+2] + prices[a+2]`, and so on — leaving only `prices[b] - prices[a]`.

This means: **any multi-day trade can be broken down into a sequence of single-day trades with the exact same total profit.** Since we're allowed unlimited transactions, we might as well break every profitable trade down into its smallest possible single-day pieces — and simply discard the days where price drops, since those contribute negative amounts we're not forced to include.

That's why a simple greedy scan — summing only the positive daily differences — produces the true maximum profit.

## Solution Code

```python
class Solution(object):
    def maxProfit(self, prices):
        """
        :type prices: List[int]
        :rtype: int
        """
        total = 0
        for i in range(1, len(prices)):
            if prices[i] > prices[i - 1]:
                total += prices[i] - prices[i - 1]
        return total
```

**Usage example:**
```python
solution = Solution()
print(solution.maxProfit([7, 1, 5, 3, 6, 4]))  # Output: 7
print(solution.maxProfit([1, 2, 3, 4, 5]))     # Output: 4
print(solution.maxProfit([7, 6, 4, 3, 1]))     # Output: 0
```

## Complexity Analysis

### Time Complexity: `O(n)`
The algorithm makes a single pass through the `prices` array, performing constant-time work (a comparison and possibly an addition) at each step. There are no nested loops and no repeated scans.

### Space Complexity: `O(1)`
Only a fixed number of variables (`total`, loop index `i`) are used, regardless of the size of the input array. No auxiliary data structures (arrays, hash maps, etc.) are needed.

## Alternative Approaches

While the greedy one-pass solution is the simplest and most efficient, this problem can also be solved with:

- **Dynamic Programming (state machine):** Track two states per day — "max profit if holding a stock" and "max profit if not holding a stock" — and transition between them. This generalizes well to variants of the problem (e.g., with transaction fees or cooldowns) but is `O(n)` time and `O(1)` space, offering no efficiency advantage here, just more flexibility for related problems.
- **Peak-Valley Approach:** Explicitly find local valleys (buy points) and local peaks (sell points), summing `peak - valley` for each pair. This is logically equivalent to the greedy approach but requires more bookkeeping to detect direction changes.

The greedy day-to-day comparison is preferred here because it is the most concise and directly derived from the telescoping-sum insight.

---

## Edge Cases

- **Empty or single-element array:** If `prices` has 0 or 1 elements, there are no valid day-to-day comparisons, so the loop doesn't execute and `total` correctly remains `0`.
- **Strictly decreasing prices:** No day-to-day increase ever occurs, so `total` stays `0` — correctly reflecting that no profitable trade exists.
- **Strictly increasing prices:** Every day contributes to the total, which correctly sums to `last price - first price`.
- **Flat prices (no change):** Days where `prices[i] == prices[i - 1]` add nothing, which is correct since there's no profit in a zero-change trade.

---

## Common Mistakes

- **Tracking a single global minimum (`low`) as in Problem I:** This only works for the *single-transaction* version of the problem. Since Problem II allows unlimited transactions, using a global minimum loses profit from intermediate up-and-down swings.
- **Overcomplicating with multiple tracking variables:** Some early attempts introduce variables like a "second lowest" price, but the greedy day-to-day comparison needs only one running total — no extra state is required.
- **Forgetting to compare against the *previous day* specifically:** The comparison must be `prices[i] > prices[i-1]`, not against some historical minimum or maximum.
- **Wrapping the input incorrectly:** Passing a nested list like `[[7,1,5,3,6,4]]` instead of `[7,1,5,3,6,4]` will break indexing and comparisons — always confirm the input shape matches what the function signature expects.

## Summary

This problem is a strong introduction to **greedy algorithms** and the idea that a complex-looking optimization (choosing the best set of buy/sell pairs) can often be reduced to a simple, local decision repeated over the input (capture every positive daily price change). The telescoping-sum property is the mathematical justification that makes the greedy approach provably optimal, not just a lucky heuristic. The result is an elegant `O(n)` time, `O(1)` space solution.
