# Majority Element

A Python solution to the classic "Majority Element" problem from LeetCode (Problem #169), including the full thought process, approach, and complexity analysis.

---

## 📋 Problem Statement

Given an array `nums` of size `n`, return the majority element.

The majority element is the element that appears **more than `⌊n / 2⌋` times**. You may assume the majority element always exists in the array.

### Examples

**Example 1:**
```
Input: nums = [3,2,3]
Output: 3
```

**Example 2:**
```
Input: nums = [2,2,1,1,1,2,2]
Output: 2
```

### Constraints
- `n == nums.length`
- `1 <= n <= 5 * 10^4`
- `-10^9 <= nums[i] <= 10^9`
- A majority element always exists in `nums`

---

## 💡 Intuition

The problem guarantees a majority element always exists — one value that appears more than `⌊n / 2⌋` times. That guarantee means I don't need to handle a "no majority" case; I just need an efficient way to figure out **how often each value shows up**, then pick out the one with the highest count.

The most natural way to track "how often each value shows up" is a frequency map — a structure that lets me associate each distinct number with a running count, without rescanning the array for every single element.

---

## 🧠 Approach

1. Create an empty dictionary `count` to store `value -> frequency` pairs.
2. Loop through `nums` once. For each `num`:
   - If `num` is already a key in `count`, increment its value by 1.
   - Otherwise, add it as a new key with a starting value of `1`.
3. After the loop, `count` holds the frequency of every distinct number in `nums`.
4. Use `max(count, key=count.get)` to find the key with the highest associated value. This tells Python: *"iterate over the dictionary's keys, but compare them based on what `count.get(key)` returns (their frequency), not the keys themselves."*
5. Return that key — it's the majority element.

This avoids the inefficiency of calling `nums.count(x)` inside a loop, which re-scans the whole array for every element and leads to redundant work. Instead, each element is counted exactly once, and finding the max is a single pass over the dictionary at the end.

---

## 🖥️ Solution

```python
class Solution(object):
    def majorityElement(self, nums):
        """
        :type nums: List[int]
        :rtype: int
        """
        count = {}
        for num in nums:
            if num in count:
                count[num] += 1
            else:
                count[num] = 1
        return max(count, key=count.get)


obj = Solution()
print(obj.majorityElement([2, 1, 1, 2, 2, 2]))  # Output: 2
```

---

## ⏱️ Complexity Analysis

| Metric | Complexity | Explanation |
|---|---|---|
| **Time** | `O(n)` | Building the frequency dictionary takes a single pass over `nums`. Finding the max value takes `O(k)`, where `k` is the number of distinct elements (at most `n`). Overall this is linear. |
| **Space** | `O(n)` | In the worst case, the dictionary can hold up to `n` distinct keys before the majority element dominates. |

---

## 🔍 Approach Comparison

While building this solution, a few different approaches were considered along the way:

| Approach | Time | Space | Notes |
|---|---|---|---|
| Brute force (`nums.count(x)` in a loop) | O(n²) | O(1) | Simple but re-scans the array for every element — slow on large inputs |
| **Hash map (this solution)** | **O(n)** | **O(n)** | Counts each element once, then finds the max frequency key |
| Boyer-Moore Voting Algorithm | O(n) | O(1) | Optimal — tracks a single candidate and counter, no extra data structure needed |

> 💭 **Next step to explore:** The Boyer-Moore Voting Algorithm solves this in `O(n)` time and `O(1)` space by maintaining a `candidate` and a `count` as you scan once through the array — incrementing when you see the candidate again, decrementing otherwise, and swapping candidates when the count hits zero. It's a great follow-up exercise once the hash map approach feels solid.
