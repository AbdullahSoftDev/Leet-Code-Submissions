# 121. Best Time to Buy and Sell Stock

[LeetCode Problem Link](https://leetcode.com/problems/best-time-to-buy-and-sell-stock/)

**Difficulty:** Easy
**Status:** Solved

## Problem Statement

You are given an array `prices` where `prices[i]` is the price of a given stock on the `ith` day.

You want to maximize your profit by choosing a single day to buy one stock and choosing a different day in the future to sell that stock.

Return the maximum profit you can achieve from this transaction. If you cannot achieve any profit, return `0`.

### Example 1

```
Input: prices = [7,1,5,3,6,4]
Output: 5
Explanation: Buy on day 2 (price = 1) and sell on day 5 (price = 6), profit = 6-1 = 5.
Note that buying on day 2 and selling on day 1 is not allowed because you must buy before you sell.
```

### Example 2

```
Input: prices = [7,6,4,3,1]
Output: 0
Explanation: In this case, no transactions are done and the max profit = 0.
```

## Solution: One-Pass Buy Low, Track Max Profit

### Intuition

The naive approach is to find the lowest price in the array first, then search for the highest price after it. But that fails when the true minimum occurs late in the array, after a profitable peak has already passed — like `[2,4,1]`, where buying at index 0 and selling at index 1 gives profit 2, but the global minimum (1) sits at the very end with nothing after it to sell at.

The fix is to track the **lowest price seen so far** as we scan left to right, and at each step check what profit we'd make if we sold today at that running low.

### Approach

1. Initialize `low` to the first price and `max` (best profit) to 0.
2. Iterate through the prices once:
   - If the current price is lower than `low`, update `low` to this price (found a better buy point).
   - Otherwise, calculate the profit if sold today (`prices[i] - low`), and update `max` if it's better than what we've seen.
3. Return `max` at the end.

This works because at every index, `low` always reflects the minimum price available *before* that point — so every possible sell day is checked against the best possible buy day up to that point.

### Manual trace: `[7,1,5,3,6,4]`

| i | prices[i] | compare to low | action | low | max |
|---|-----------|-----------------|--------|-----|-----|
| - | - | - | start | 7 | 0 |
| 0 | 7 | 7 < 7? no | profit = 0, max stays | 7 | 0 |
| 1 | 1 | 1 < 7? yes | new low | 1 | 0 |
| 2 | 5 | 5 < 1? no | profit = 4, max updates | 1 | 4 |
| 3 | 3 | 3 < 1? no | profit = 2, max stays | 1 | 4 |
| 4 | 6 | 6 < 1? no | profit = 5, max updates | 1 | 5 |
| 5 | 4 | 4 < 1? no | profit = 3, max stays | 1 | 5 |

Result: `max = 5` ✅

### Complexity

| | Naive (min-first, then search max after) | One-pass (track running low) |
|---|---|---|
| Time | O(n²) worst case if re-scanning, or O(n) but **incorrect** on cases like `[2,4,1]` | O(n) — single pass |
| Space | O(1) extra (but logically buggy — misses valid buy/sell pairs) | O(1) extra, genuinely correct |

### Code

```python
class Solution(object):
    def maxProfit(self, prices):
        """
        :type prices: List[int]
        :rtype: int
        """
        low = prices[0]
        max = 0

        for i in range(len(prices)):
            if prices[i] < low:
                low = prices[i]
            else:
                profit = prices[i] - low
                if profit > max:
                    max = profit

        return max
```
